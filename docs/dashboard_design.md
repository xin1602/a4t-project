# BitoGuard 詐欺偵測儀表板 — 設計思考文件

> 使用者：幣託交易所內部人員（合規/風控/客服/資安）  
> 目標：以 Design Thinking 方法，從使用者角度出發，定義儀表板需求

---

| 角色 | 職責 | 主要關注點 |
|------|------|-----------|

## 二、User Stories（使用者故事）

### Epic 1：風險總覽

**US-01**  
身為風控分析師，  
我想要在登入後立即看到今日高風險用戶數量與趨勢，  
以便快速掌握當日工作量與異常狀況。

**US-02**  
身為風控分析師，  
我想要看到詐欺風險分布的視覺化圖表（如風險分數直方圖），  
以便了解整體用戶群的風險輪廓，判斷閾值是否需要調整。

**US-03**  
身為資安工程師，  
我想要監控模型預測的詐欺率趨勢（每日/每週），  
以便偵測是否有新型詐欺手法導致異常飆升。

---

### Epic 2：用戶風險查詢

**US-04**  
身為風控分析師，  
我想要輸入 user_id 後立即看到該用戶的完整風險畫像，  
以便在接到申訴或需要審查時快速做出判斷。

**US-05**  
身為客服人員，  
我想要看到用白話文寫成的風險診斷說明（而非技術特徵名稱），  
以便向用戶解釋帳號被標記的原因。

**US-06**  
身為風控分析師，  
我想要看到該用戶的 SHAP 特徵貢獻長條圖，  
以便理解哪些行為最影響模型判斷，並決定是否認同。

**US-07**  
身為風控分析師，  
我想要看到用戶的交易時間熱力圖（小時 × 星期），  
以便直觀判斷是否有深夜/週末異常交易模式。

---

### Epic 3：圖網絡分析

**US-08**  
身為風控分析師，  
我想要以選定用戶為 root，看到以他為中心向外擴散的關聯用戶網絡圖（僅顯示有直接資金往來的節點，不顯示全體），  
以便識別是否與其他已知詐欺帳號有直接或間接連結。

**US-08a**  
身為風控分析師，  
我想要在每個網絡節點上直接看到該用戶的關鍵特徵摘要（如風險分數、總交易量、hub score）以及是否被預測為黑名單，  
以便不需要逐一點開每個節點就能快速判斷整個群聚的風險程度。

**US-09**  
身為資安工程師，  
我想要在網絡圖中以顏色區分節點狀態（已確認詐欺紅色 / 模型預測高風險橘色 / 正常灰色 / 待審查黃色），  
以便快速識別高風險群聚（cluster）的範圍與密度。

**US-10**  
身為合規人員，  
我想要查看特定用戶的 hub score 與 authority score 解釋，  
以便在 AML 報告中說明該用戶在資金流網絡中的角色。

---

### Epic 6：LLM 智能問答

**US-16**  
身為風控分析師，  
我想要在查看某用戶的風險頁面時，能用自然語言提問（例如「為什麼這個人被判定為黑名單？」「他的 hub score 高代表什麼？」），  
以便在不熟悉模型特徵定義的情況下，也能快速理解判斷依據。

**US-17**  
身為風控分析師，  
我想要在圖網絡頁面中，針對整個群聚提問（例如「這個群聚的資金流向模式是什麼？」「哪個節點最可疑？」），  
以便從整體視角理解詐欺網絡的運作方式。

**US-18**  
身為客服人員，  
我想要讓 LLM 根據用戶的特徵自動生成一段可以直接對外說明的白話文解釋，  
以便在處理申訴時有標準化的說明依據，不需要自己翻譯技術術語。

---

### Epic 7：新用戶 / 新資料即時預測

**US-19**  
身為資安工程師，  
我想要在儀表板上手動輸入或上傳一筆新用戶的交易資料，觸發即時推論並立即看到風險分數，  
以便在新用戶完成 KYC 或發生可疑交易時快速評估風險。

**US-20**  
身為資安工程師，  
我想要上傳一批新用戶的 CSV 資料進行批次預測，並在完成後下載結果，  
以便定期（如每日）更新整體用戶的風險評分。

**US-21**  
身為風控分析師，  
我想要在新用戶被預測為高風險後，立即在儀表板上看到通知，並能直接跳轉到該用戶的風險查詢頁，  
以便第一時間介入審查，不需要等待下一次批次更新。

---

### Epic 4：案件管理

**US-11**  
身為風控分析師，  
我想要對高風險用戶標記處理狀態（待審查 / 已凍結 / 誤判放行），  
以便追蹤案件進度，避免重複審查。

**US-12**  
身為合規人員，  
我想要匯出特定時間範圍內的高風險用戶清單與診斷報告（PDF/CSV），  
以便提交給監管機關或進行內部稽核。

**US-13**  
身為風控主管，  
我想要看到各分析師的案件處理量與平均處理時間，  
以便評估團隊效率並合理分配工作。

---

### Epic 5：模型監控

**US-14**  
身為資安工程師，  
我想要調整預測閾值並即時看到對應的 Precision / Recall 變化，  
以便在不同業務情境下（嚴格/寬鬆）動態調整模型行為。

**US-15**  
身為資安工程師，  
我想要看到模型的 CV F1 歷史趨勢與各實驗版本比較，  
以便評估是否需要重新訓練模型。

## 三、Acceptance Criteria（驗收標準）

### AC-01：風險總覽頁

- [ ] 頁面載入時間 < 3 秒
- [ ] 顯示今日新增高風險用戶數（status=1）
- [ ] 顯示過去 30 天詐欺率趨勢折線圖
- [ ] 顯示風險分數分布直方圖（全體 63,770 用戶）
- [ ] 顯示 Top 10 最高風險用戶快速連結

### AC-02：用戶風險查詢頁

- [ ] 支援 user_id 精確搜尋，回應時間 < 1 秒
- [ ] 顯示風險分數（0–1）與對應風險等級（低/中/高/極高）
- [ ] 顯示 SHAP Top 5 特徵貢獻橫向長條圖（正向紅色、負向藍色）
- [ ] 顯示白話文風險診斷書（來自 risk_reports.json 或 LLM 生成）
- [ ] 顯示交易時間熱力圖（24 小時 × 7 天）
- [ ] 顯示法幣 / 加密貨幣 / 交易量的關鍵數字卡片

### AC-03：圖網絡分析頁

- [ ] 以選定 user_id 為 root，向外擴散呈現有直接資金往來的鄰居節點（僅顯示有邊的節點，不顯示孤立節點）
- [ ] 支援 1-hop（直接關聯）與 2-hop（間接關聯）切換，預設 1-hop
- [ ] 每個節點顯示 tooltip 或 inline 標籤，包含：user_id、風險分數、黑名單狀態（是/否）、Top 3 重要特徵數值（total_trade_volume、hub_score、crypto_net_flow）
- [ ] 節點顏色區分：已確認詐欺（紅）/ 模型預測高風險（橘）/ 待審查（黃）/ 正常（灰）
- [ ] 邊的方向與粗細反映資金流向與金額大小
- [ ] 點擊節點可跳轉至該用戶的風險查詢頁
- [ ] 顯示 root 節點的 hub score 與 authority score 數值及角色說明（資金分發者 / 資金接收者）
- [ ] 支援縮放、拖曳、節點固定互動
- [ ] 圖載入時間 < 2 秒（1-hop，節點數上限 50）

### AC-06：LLM 智能問答

- [ ] 用戶風險查詢頁與圖網絡頁均提供對話輸入框
- [ ] 後端在呼叫 LLM 前，自動組裝以下 context 傳入：
  - 用戶基本資訊（user_id、職業、收入來源）
  - 模型預測結果（風險分數、黑名單狀態）
  - SHAP Top 10 特徵名稱、數值、貢獻方向
  - 圖特徵（hub_score、authority_score、in/out degree）
  - 特徵定義字典（將技術名稱對應到業務說明，例如 `twd_avg_daily_tx` → 「法幣每日平均交易次數」）
  - 當前頁面情境（單一用戶查詢 / 圖網絡群聚分析）
- [ ] 圖網絡頁的問答額外傳入：群聚內所有節點的風險分數與黑名單狀態摘要
- [ ] LLM 回答以繁體中文呈現，避免直接輸出特徵英文名稱
- [ ] 支援多輪對話（保留對話歷史 context）
- [ ] 回應時間 < 5 秒（使用串流輸出 streaming）

### AC-07：新用戶 / 新資料即時預測

- [ ] 提供「單筆預測」表單：輸入用戶交易摘要數值（各特徵欄位），點擊送出後 < 2 秒回傳風險分數
- [ ] 提供「批次預測」上傳：接受 CSV 格式（欄位對應現有 34 個特徵），完成後可下載結果 CSV
- [ ] 批次預測完成後，高風險用戶（分數 > 閾值）自動出現在案件管理列表，並標示「新批次」來源
- [ ] 儀表板右上角顯示即時通知：「新批次預測完成，發現 X 位高風險用戶」，點擊可跳轉案件管理頁
- [ ] 單筆預測結果頁面與既有用戶查詢頁面格式一致（SHAP 圖、診斷書、圖網絡）
- [ ] 批次預測支援排程設定（每日 00:00 自動執行，可在模型監控頁設定）

### AC-04：案件管理頁

- [ ] 顯示所有 status=1 用戶的可排序列表（依風險分數、處理狀態）
- [ ] 支援批次標記處理狀態
- [ ] 支援匯出 CSV（user_id, risk_score, status, 處理狀態, 診斷摘要）
- [ ] 支援匯出 PDF 報告（含 SHAP 圖表）
- [ ] 操作記錄留存稽核軌跡（操作人員、時間戳記、動作）

### AC-05：模型監控頁

- [ ] 顯示當前模型版本、訓練日期、CV F1 分數
- [ ] 提供閾值滑桿（0.1–0.9），即時更新 Precision / Recall / F1 預覽
- [ ] 顯示各實驗版本的 F1 歷史比較表
- [ ] 顯示 SHAP 全局特徵重要性長條圖（Top 20）

## 六、設計原則

1. 可解釋優先：每個風險判斷都必須有人類可讀的理由，不能只顯示分數
2. 行動導向：每個頁面都有明確的下一步動作（標記 / 凍結 / 匯出）
3. 漸進揭露：客服看簡單說明，分析師可展開技術細節（SHAP 值、特徵數字）
4. 稽核可追溯：所有操作留存記錄，支援監管查核
